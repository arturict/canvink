# OneNote use-case coverage

## Static capability matrix, not an acceptance percentage

Canvink does not claim 80% feature parity with OneNote, 80% personal-workflow acceptance, or an 80% release decision. This matrix is only a static inventory of selected everyday capabilities in the current source tree. Its rows are not equal measurements of user value, fidelity, reliability, or readiness, so they are not added into a product-acceptance percentage. Implemented source with an unrun external or personal gate is labeled separately and does not become a shipped or accepted outcome.

The outcomes are based on Microsoft's documented OneNote basics for [capturing and organizing notes](https://support.microsoft.com/en-US/OneNote/basic-tasks-in-onenote-for-windows-10), [pages and subpages](https://support.microsoft.com/en-us/onenote/organize-your-notes), [formatting notes and tags](https://support.microsoft.com/en-us/onenote/take-and-format-notes), [search](https://support.microsoft.com/en-US/OneNote/search-for-notes-in-onenote-for-windows-10), [PDF printouts](https://support.microsoft.com/en-us/onenote/onenote-for-mac-help-and-learning/insert-pdf-printouts-into-notes-in-onenote-for-mac), [notebook export](https://support.microsoft.com/en-US/OneNote/export-and-import-onenote-notebooks), and [offline sync behavior](https://support.microsoft.com/en-US/OneNote/onenote-help-and-learning/sync-a-notebook-in-onenote). The matrix measures Canvink implementation evidence and acceptance boundaries, not Microsoft's product completeness.

## Matrix

| --- | --- | --- | --- |
| 1 | Capture a thought immediately | Supported in automated coverage | Blank Quick note and directly focused text editor; onboarding is optional and resumable. |
| 2 | Write and structure a longer note | Supported in automated coverage | Movable canonical Automerge/ProseMirror rich text with headings, marks, links, lists, check items, quotes, code, and tables. Portable projections are used for import/export instead of becoming a second live authority. |
| 3 | Keep an actionable checklist | Supported in automated coverage | Editable, movable checklist objects with multiple open or completed items. |
| 4 | Handwrite or sketch ideas | Supported in automated coverage | Pressure-aware pen, highlighter, eraser, selection, movement and resize share one canvas. A visible per-page ruler can be moved and freely rotated; pen and straight tools snap to its edge through zoom and pan. The exact 45-minute real-pen performance and ergonomics gate remains open, and handwriting recognition is absent. |
| 5 | Mix text, ink, and visual references | Supported in automated coverage | Rich text, checklists, ink, shapes, images, PDFs, and attachments share one spatial page. Original asset bytes remain content-addressed outside the CRDT and are preserved in complete `.canvink` bundles. |
| 6 | Organize work into notebooks and sections | Supported in automated coverage | Named notebooks, sections, pages, and nested subpages. Notebook and section order can be changed by drag-and-drop or equivalent arrow/menu controls and survives reload. |
| 7 | Restructure a notebook as it grows | Supported in automated coverage | Create subpages; duplicate, reorder, move or copy pages, sections, and notebooks; and trash, restore, or permanently delete through guarded schema-v2 graph revisions. Cross-root operations reopen the committed graph before reporting success. |
| 8 | Mark and revisit important or actionable pages | Supported in automated coverage | `PageDoc` preserves tags and open/done task state from checked migration and OneNote import. OneNote `data-tag` variants normalize into known tags, checklist state, or a safe `onenote:` tag and are indexed locally. Page settings add, remove, and suggest tags and set the page task state to open, done, or none; manual and imported tags share one normalizer, and the page limit is bounded. Free-form tag colours, icons, and per-object tags are not implemented. |
| 9 | Find a note by remembered content | Supported in automated coverage | Rebuildable local schema-v2 index across notebook/section/page titles, tags, task state, rich text, check items, extracted PDF text, and explicitly accepted local OCR text. Handwriting recognition is not implemented. |
| 10 | Review open work across pages | Supported in automated coverage | Checklist text, indexed tags, and task metadata participate in the local projection. Search accepts `tag:<name>`, `is:open`, `is:done`, and `is:task` operators alone or combined with free text, the same operators back the task and tag dropdowns, and a cross-page task review lists every marked page with its state and tags. Saved searches and due dates are not implemented. |
| 11 | Continue after reload or without a network | Supported in automated coverage | Schema-v2 authority persists in desktop SQLite or browser IndexedDB; the browser shell can reopen after its first successful load. Optional sync uses a durable outbox and catch-up, but offline local use does not depend on sync. |
| 12 | Recover, back up, and hand off a static copy | Supported in automated coverage | Fail-closed activation recovery, verified manual/automatic/trash history, copy-based restore, PDF/PNG/Markdown export, and complete additive `.canvink` bundle import/export are implemented. Source-backed PDF pages are copied structurally and receive a sanitized Canvink overlay rather than flattening the original page to a screenshot. History is not a device backup; personal backup and representative PDF-fidelity drills remain open. |
| 13 | Keep the same live notebook synchronized across devices | Implemented; live gate open | An opt-in encrypted Automerge sync client, durable outbox/cursors, catch-up, key envelopes, device approval/recovery, and Appwrite adapters are implemented and deterministically tested. The Appwrite project is intentionally undeployed; two real accounts, target devices, restoration, and the exact 60-minute report remain unaccepted. |
| 14 | Co-edit or share a live notebook with other people | Implemented; live gate open | Owner/editor/viewer roles, invitations, encrypted change/asset transport, bounded presence, and conflict badges are implemented. Real membership/revocation timing and Realtime behavior against deployed Appwrite remain unrun; comments are not claimed. |
| 15 | Capture through OCR, audio, email, or a web clipper | Partial | Local Windows OCR and indexing of explicitly accepted OCR text are implemented. Representative personal scans and installed language packs remain unaccepted; handwriting recognition, audio recording, email ingestion, and a browser clipper are absent. |

Result: the matrix records static implementation coverage, partial UI paths, and open live gates; it deliberately produces no personal acceptance percentage. A row backed by automation can still require physical hardware, representative private documents, a real Microsoft Entra/Graph account, or another external system before it is accepted for actual use.

## Release rule

The matrix may only mark a source capability supported in automated coverage when its end-to-end local path is automated or has reproducible local evidence. Deterministic mocks do not turn an undeployed external service, real-account import, physical-device session, or personal OCR/PDF comparison into live evidence. Partial capabilities and live gates remain explicit in the boundary column. Public copy must continue to say `public alpha` until the separate publication gates in [beta readiness](beta-readiness.md) and the [acceptance matrix](acceptance-matrix.md) are complete and approved.
